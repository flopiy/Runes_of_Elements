# Руни Стихій: Онлайн — «Башта новачка», ігровий екран, меню та онлайн

# Project Overview
- **Game Title:** Руни Стихій: Онлайн (Runes of Elements Online)
- **High-Level Concept:** Кооперативна гра з картами та жетонами для 2–4 магів: заклинання збираються з рун за формулою «Стихія + Форма», а загін піднімається поверхами Башти, відбиваючи хвилі монстрів із Розлому.
- **Players:** соло з ботами, локальний hot-seat, онлайн-кооператив до 4 гравців (кімната за кодом); вільні місця займають боти.
- **Inspiration / Reference Games:** Slay the Spire (підйом поверхами), Dice Throne, Magic: The Gathering.
- **Tone / Art Direction:** темне фентезі, ковані рамки карток, пурпуровий Розлом, кольори стихій за GDD §10.
- **Target Platform:** PC (StandaloneWindows64), надалі WebGL.
- **Screen Orientation / Resolution:** альбомна, 1920×1080 (масштабування від 1280×720).
- **Render Pipeline:** URP (PC_RPAsset).

# Game Mechanics
## Core Gameplay Loop
**Башта новачка = 10 поверхів × 3 хвилі (30 битв).** Кожна хвиля — це звичайна битва за правилами v1.1: ходи магів → ходи монстрів → відновлення (+5), і так доки поле не очиститься.

| Поверх | Хвиля 1 | Хвиля 2 | Хвиля 3 |
|---|---|---|---|
| 1 | L1×2 | L1×2 | L1×3 |
| 2 | L1×3 | L1×3 | L1×4 |
| 3 | L1×3 | L2×1 + L1×2 | L2×2 |
| 4 | L2×2 | L2×2 + L1×1 | L2×3 |
| 5 (міні-бос) | L2×2 | L2×2 + L1×1 | **L3×1** + L1×2 |
| 6 | L2×3 | L3×1 + L1×2 | L3×1 + L2×1 |
| 7 | L3×1 + L2×1 | L3×1 + L2×1 + L1×1 | L3×2 |
| 8 | L3×1 + L2×2 | L3×2 + L1×1 | L3×2 + L2×1 |
| 9 | L3×2 + L1×2 | L3×2 + L2×1 | L3×3 |
| 10 (бос) | L2×3 | L3×1 + L2×2 | **Бос** + L1×2 |

Правила між хвилями й поверхами (адаптація GDD §5.7 під довшу кампанію):
- **Після хвилі 1 або 2:** живі маги отримують +3 HP. Вибулі маги лишаються поза грою до кінця поверху. Руну не дають. Концентрація повертається до стартової.
- **Після хвилі 3 (поверх пройдено):** повна нагорода за GDD: живі отримують +1 випадкову руну та +3 HP, вибулі повертаються з 3 HP, перевіряється ліміт руки. Показується екран «Поверх N пройдено».
- «Скинути карту благословення» можна після **3-го поверху** (замість «після 3-ї битви»). «Шепіт Розлому» спрацьовує на **поверсі 3, хвиля 1**.
- **Колоди монстрів перемішуються наново**, коли вичерпуються: беруться всі карти рівня, крім тих, що зараз на полі. Інакше 8/4/4 карт не вистачить на 30 битв.
- Перемога — бос на 10-му поверсі переможений. Поразка — загинули всі маги. Після поразки показується рекорд: найвищий поверх і хвиля.
- Опційний параметр `FloorSpec.MonsterHpBonus` (за замовчуванням 0) — для балансу після симуляції ботами.

MDA: «Aesthetics = Challenge + Fellowship». Хвилі всередині поверху дають коротку петлю напруги без повного відпочинку, бо вибулі не повертаються одразу. Поверх дає велику петлю нагороди: руна, повернення вибулих, видимий прогрес у Башті.

## Controls and Input Methods
New Input System (мишка, клавіатура):
- ЛКМ по руні в руці, потім по комірці Стихії/Форми — заміна руни (крок 2).
- ЛКМ по комбінації (Стихія + Форма) на картці мага — вибір заклинання. Допустимі цілі підсвічуються: вертикаль для Променя, ряд для Сфери. ЛКМ по монстру — каст.
- Кнопки: «Медитувати», «Завершити хід», «Крижаний полон» (лише для Кріоманта), «Прийняти / Перекинути / Дзеркало» (рішення щодо кидка).
- Esc — пауза/меню. Hover над карткою або станом — підказка з текстом правила.
- Hot-seat: керує той гравець, чий зараз хід. Онлайн: керувати можна лише своїм місцем (seat).

**Data / Editor:**
- `CampaignDefinition`: поле `List<FloorSpec> Floors`, `GameDatabase.BuildContent()` заповнює Tower. `RunesDataGenerator` генерує поверхи.

**Мережа (`Assets/Scripts/RunesOfElements/Network/`, asmdef `RunesOfElements.Network`):**
- Топологія: **host-authoritative** через Unity Multiplayer Services Sessions + Relay (код кімнати = `Session.Code`). `RulesEngine` і RNG працюють **лише на хості** (GDD §11: «сервер-авторитетна сесія»).
- `RoENetworkService`: ініціалізація UGS, анонімна автентифікація, `CreateSessionAsync` (MaxPlayers 4, `WithRelayNetwork()`), `JoinSessionByCodeAsync`, вихід із сесії.
- `NetworkGameSession : NetworkBehaviour, IGameSession`:
  - `[Rpc(SendTo.Server)] SubmitCommandRpc(NetCommand cmd, RpcParams p)` → хост перевіряє, що `cmd.Seat` належить `p.Receive.SenderClientId`, і виконує `Submit`.
  - `[Rpc(SendTo.NotServer)] SnapshotRpc(string json)` після кожної зміни стану; `[Rpc(SendTo.SpecifiedInParams)] RejectedRpc(string reason)`.
  - Лобі-стан: `NetworkList<SeatInfoNet>` (clientId, ім'я, маг, готовність) + налаштування боса.
  - Від'єднання гравця → його місце переходить боту. Таймаут ходу 60 с → бот.
- `NetworkManager` (з `UnityTransport`) у сцені меню з `DontDestroyOnLoad`. Сцену гри завантажує `NetworkManager.SceneManager.LoadScene`.

**Сцени:**
- Нова `Assets/Scenes/RoE_MainMenu.unity` (меню + лобі + NetworkManager + EventSystem).
- `RunesOfElements_Dungeon.unity` — додати `RoEBootstrap`, `BoardPresenter`, `UIDocument` (GameHud), `EventSystem`, `NetworkObject` з `NetworkGameSession` (in-scene placed).
- Build Settings: `RoE_MainMenu` (індекс 0), `RunesOfElements_Dungeon` (1). Сцени Blocks лишаються після них.

# Verification & Testing
- **EditMode (NUnit):** усі наявні 30+ тестів правил + нові тести Башти (крок 3) + JSON round-trip snapshot/команд. Стрес: 200 кампаній ботами без винятків, інваріанти концентрації 0..5 і HP тримаються, жодна гра не зависає.
- **Баланс:** симуляція 500 ігор → середня кількість раундів на хвилю, winrate, на якому поверсі найчастіше програють. Звіт у консоль.
- **Play Mode (вручну + скрипт):** соло-гра. Заміна руни → обмеження «1 за хід»; каст Променя/Сфери підсвічує правильні цілі; медитація дає +2; між хвилями немає руни, а вибулий лишається поза грою; після 3-ї хвилі є руна, повернення вибулих і екран поверху; на 10-му поверсі є бос.
- **Hot-seat:** кнопки активні лише для поточного людського місця.
- **Онлайн:** Multiplayer Play Mode (2 віртуальні гравці, пакет `multiplayer.playmode` уже встановлено). Хост створює кімнату → клієнт приєднується за кодом → кожен керує лише своїм магом; команда клієнта на чужому місці відхиляється; від'єднання клієнта → бот; кидки бачать обидва однаково (RNG лише на хості).
- **Консоль:** 0 помилок компіляції/рантайму; збірка Windows64 стартує з `RoE_MainMenu`.

**Ризики / припущення:** (1) кирилиця в TMP/UITK-шрифті; (2) для онлайну потрібен прив'язаний Unity Cloud Project (Services → Project ID), інакше Relay не запуститься — перевірю й повідомлю; (3) таблицю поверхів і правило «вибулі до кінця поверху» можна легко змінити в `DefaultContent`.

# Project Overview
- **Game Title:** Руни Стихій: Онлайн.
- **High-Level Concept:** Головне меню перед входом у «Башту новачка»: кам’яна магічна вежа, сяючий портал біля підніжжя та компактна панель запуску походу. Вежа візуально пояснює тему підйому поверхами без зайвих бойових показників.
- **Players:** наявні соло з ботами та локальний hot-seat; онлайн-режим лишається окремою функцією, його працездатність не оголошується перевіреною в межах цієї візуальної роботи.
- **Inspiration / Reference Games:** Slay the Spire — тема підйому баштою; темне фентезі наявних карток.
- **Tone / Art Direction:** темний камінь, бронза, пурпурова магія, теплі вікна; читабельні невеликі написи, без перевантаження екрану.
- **Target Platform:** StandaloneWindows64, Unity 6000.3.10f1.
- **Screen Orientation / Resolution:** landscape; основний макет 1920×1080 з масштабуванням через наявні PanelSettings; додаткові перевірки 1280×720 та 960×540.
- **Render Pipeline:** підтверджено URP, `PC_RPAsset`. Джерельна сцена використовує realtime-освітлення; запікання світла для меню не потрібне.

# Game Mechanics
## Core Gameplay Loop
Меню → вибір соло/hot-seat → налаштування загону → початок наявної кампанії у `RunesOfElements_Dungeon` → повернення до меню. Правила хвиль, характеристики магів, портрети, HP, бойові анімації та раніше опущені HUD-панелі не змінюються.

## Controls and Input Methods
- Зберегти New Input System та мишу/клавіатуру для UI Toolkit.
- Кнопки: «Сольна гра», «Гаряче місце», «Правила», «Вихід»; у налаштуваннях — вибір магів, боса, перегріву, «Назад» і «Почати похід».
- Не запускати підключення до мережі автоматично при відкритті меню.
- Наявні заготовки кнопок створення/приєднання до онлайн-кімнати не перетворювати на фіктивно працюючі. Якщо немає повного підключеного lobby-flow, показати їх як недоступні з короткою підказкою; реалізацію мережевого лобі винести за межі цього погодження.

# Key Asset & Context
## Перевірений поточний стан
- `Assets/UI/RunesOfElements/MainMenu.uxml` існує, містить меню, налаштування та правила, але має inline-стилі й некоректний-looking GUID у посиланні на stylesheet; замінити посилання перевіреним локальним `RoE.uss` і новим `MainMenu.uss`.
- За індексом залежностей сцен, **жодна наявна сцена не використовує MainMenu.uxml**. Окрема сцена головного меню та MainMenuController не знайдені.
- Build Settings нині починаються з `Assets/Core/TestScenes/[BB] Core.unity`, де підключено старі `CardGame.*` і Blocks-мережевий UI. Цю сцену не переробляти й не видаляти.
- `GameLaunchParams` у `Assets/Scripts/RunesOfElements/Presentation/Session/IGameSession.cs` вже має `Mode`, `Setup` і `DefaultSolo()`.
- `RoEBootstrap` читає ці параметри і створює локальну сесію для бойової сцени. `GameHudController` повертається через `SceneManager.LoadScene(0)`, тому нове меню має стати першою build-сценою.
- `RunesOfElements.Presentation.asmdef` посилається на Core, Data та Unity.InputSystem; прямого посилання на Network немає. Не створювати циклічних залежностей заради кнопок меню.
- Підтверджено URP-матеріали каменю, бронзи, пурпурових рун і порталу у `Assets/Arena/Dungeon/Materials/`.
- У джерельній бойовій сцені 16 realtime-світильників (2 directional та 14 point), ambient Trilight; LightingSettings не призначено. Не копіювати весь набір світла у меню й не змінювати бойове освітлення.

# Implementation Steps
1. **Перед реалізацією повторно перевірити залежності і стан меню.** Зберегти користувацькі незбережені сцени тільки після явного підтвердження або не закривати їх. Перевірити Input backend, PanelSettings, дані загону й способи побудови GameSetup. **Dependencies:** погодження цієї редакції.
2. **Створити оформлення MainMenu.** Переробити `MainMenu.uxml`, додати `MainMenu.uss`, зберегти всі потрібні імена елементів та текст правил. Стилі тільки меню; не переносити бойовий HUD. Один раз зберегти й перевірити UXML/USS після складання. **Dependencies:** крок 1.
3. **Побудувати MenuTower.prefab і матеріали.** Створити читабельний силует високої кам’яної вежі, входу й порталу. Декоративні об’єкти не потребують колайдерів чи фізики. Розташувати вікна/магічні вставки так, щоб вежа не виглядала одним циліндром. **Dependencies:** крок 1, макет кроку 2.
4. **Створити RoE_MainMenu.unity.** Розташувати вежу та камеру відповідно до UI. Додати один основний directional для каменю та невелику кількість point-акцентів біля порталу/входу. Сяючі вставки — візуальне світіння матеріалу, навколишній камінь освітлюють реальні світильники; не обіцяти emissive GI без bake. Не додавати light probes/APV/post-processing за межами потрібного оформлення. Призначити UIDocument наявні PanelSettings і MainMenu.uxml. **Dependencies:** кроки 2–3.
5. **Підключити MainMenuController.** Соло і hot-seat відкривають налаштування загону; запуск формує існуючий GameSetup і завантажує `RunesOfElements_Dungeon` за перевіреним scene-path. Правила відкривають/закривають модальне вікно, «Назад» повертає до title-view, «Вихід» завершує player-build. Зберегти стан вибору при поверненні між панелями. Онлайн не підключати автоматично; відсутній flow явно позначити. **Dependencies:** кроки 1–2, 4.
6. **Підключити старт гри.** Оновити Build Settings описаним порядком, не видаляючи старі сцени. Перевірити повернення бойового HUD до index 0 без редагування правил гри. **Dependencies:** кроки 4–5.
7. **Візуальне та функціональне полірування.** Знімок саме Game View у Play Mode; перевірити видимість усієї вежі, вікон, порталу та кнопок. За потреби обмежено підкоригувати камеру/матеріали/освітлення. Видалити тільки тимчасові тестові скрипти/скриншоти після перевірки. **Dependencies:** кроки 2–6.

# Verification & Testing
- UXML/USS імпортуються без нових помилок; немає невірних stylesheet-посилань або відсутніх named-кнопок.
- Запуск першої build-сцени показує нове меню та вежу, а не стару арену/обведені панелі/автопідключення.
- Screenshot у Play Mode при 1920×1080, 1280×720, 960×540: верх вежі, основа і портал видимі; кнопки не перекривають важливі частини; написи не завеликі; діалоги не обрізаються.
- Миша й клавіатурний фокус працюють; disabled-кнопки не запускають недоступних функцій.
- Соло → налаштування → старт → наявна бойова сцена з обраним людським магом та ботами.
- Hot-seat → налаштування → старт → правильний LaunchMode і людські місця; не підміняти цей режим соло.
- Вибір магів/боса/перегріву, «Назад», «Правила», «Зрозуміло», «Вихід» працюють за призначенням.
- Повторне відкриття/перебудова UI не додає дубльованих callback-підписок.
- Повернення з бою відкриває нове меню; бойові HP, картки, механіка і останні HUD-зміни зберігаються.
- Console: немає нових compile/runtime errors; жодна онлайн-сесія не стартує сама по собі. Працездатність мережевого лобі не входить до критеріїв цього етапу.
- Не запускати повну перегенерацію GameDatabase чи bake сцени бою під час роботи над меню.
